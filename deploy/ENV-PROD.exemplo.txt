# eckko.ai — exemplo de variáveis de PRODUÇÃO.
#
# ⚠️ NA VPS ESTE ARQUIVO SE CHAMA `.env`, NÃO `.env.prod`.
# O Docker Compose só carrega automaticamente um arquivo chamado `.env` no
# diretório do projeto (nenhum dos dois docker-compose*.yml declara
# `env_file:` — confirmado por leitura nesta rodada, DEPLOY-4 item 5). Um
# `.env.prod` na mesma pasta é só um arquivo de texto para o Compose: as
# variáveis dele NUNCA seriam lidas. Copie este conteúdo para `/opt/twinai/.env`
# na VPS (mesmo diretório de onde `docker compose ... up -d` for rodado).
#
# REGRA DESTE ARQUIVO: variável comentada (#VAR=) = "não vai receber valor
# nesta rodada, o container usa o próprio default". Variável presente mas
# vazia (VAR=) é OUTRA COISA — para duas delas (DOCS_DIR, UPLOADS_DIR) o
# código lê com `??`, que NÃO cai para o default do container quando a
# variável existe e está vazia (só quando ela está AUSENTE). Uma linha
# `VAR=` esquecida em branco pode apagar um caminho que devia ficar com o
# default embutido. Por isso: nunca vazio, ou comentado, ou preenchido.
# ============================================================================

# --- Domínio e portas ---
BASE_DOMAIN=eckkoai.com
BACKEND_PORT=4000
FRONTEND_PORT=5173

# A porta de DEV (8090) sobrevive no override de produção porque
# docker-compose.prod.yml substitui o `command`/`volumes` do traefik mas não
# o `ports:` do arquivo base — e o Compose CONCATENA listas de `ports` entre
# arquivos -f, não substitui (mesma regra de merge documentada no comentário
# de `volumes: !override` do próprio docker-compose.prod.yml). Resultado
# MEDIDO nesta rodada (`docker compose ... config`): o traefik publica TRÊS
# portas, não duas — ${TRAEFIK_HTTP_PORT:-8090}:80, 80:80 e 443:443. As duas
# últimas são literais no arquivo (não vêm de variável, não há como ajustá-las
# por aqui). Prender a de dev em loopback fecha o único ponto ajustável por
# .env sem editar o compose:
TRAEFIK_HTTP_PORT=127.0.0.1:8090
